## 0. 开发指南与设计偏好

### 0.1 页面结构

根布局由 **`App.vue`** 提供：`TabBar` 使用 **`fixed={false}`** 置于底部文档流，中间 **`flex-1 overflow-y-auto`** 承载各页；各 **`View`** 根节点用 **`min-h-full`**（不再用 `min-h-screen`），避免整页高度把底栏挤出视口（影响文档截图与真机观感）。

```vue
<template>
  <div class="min-h-full bg-gradient-to-b from-blue-50 to-white pb-6">
    <header class="sticky top-0 z-10 bg-white/80 backdrop-blur-sm shadow-sm px-4 py-3">
      <!-- 导航内容 -->
    </header>
    <main class="px-4 py-6">
      <!-- 页面内容 -->
    </main>
  </div>
</template>

<script setup lang="ts"></script>
<style scoped lang="scss"></style>
```

### 0.2.1 边框与分隔规范

**设计原则：极简、去边框化，用背景色和阴影区分层级。**

| 场景 | 做法 | 示例 |
|------|------|------|
| 按钮边框 | **禁止使用 border** | 用背景色区分主次 |
| 卡片边框 | **禁止使用 border** | 用 shadow-sm 或背景色 |
| 菜单项分隔 | **不用 border 分隔线** | 靠留白和分组背景区分 |
| 分组标题栏 | 无底部边框 | `bg-gray-50` 背景 + `text-gray-500` 文字 |
| Logo 容器 | 无白背景无边框 | 直接展示图标 |
| 输入框/表单 | 使用 Vant 默认样式 | 特殊情况单独处理 |

### 0.3 交互与布局

**设计原则：极简、轻盈、高级感 — 轻阴影、去边框。**

**交互类名：**
- 按钮点击：`active:scale-95 transition-all duration-300`
- 主按钮阴影：`shadow-sm`，hover 时 `hover:shadow-md`
- 卡片阴影：`shadow-sm`
- 毛玻璃：`bg-white/80 backdrop-blur-sm`
- 圆角-按钮：`rounded-full`
- 圆角-卡片：`rounded-xl`
- 文本链接 hover：`hover:opacity-80 transition-opacity`（不用下划线）

**按钮样式：**

| 类型 | 类名 | 适用场景 |
|------|------|----------|
| 主按钮 | `bg-gradient-to-r from-blue-600 to-blue-700 text-white shadow-sm hover:shadow-md` | 主要操作、强调按钮 |
| 次按钮（未选中） | `bg-gray-50 text-gray-600 hover:bg-gray-100` | 次要操作、未选中状态 |
| 胶囊标签按钮 | `bg-blue-50/50 text-blue-600 hover:bg-blue-100/50` | 顶部导航、标签按钮 |
| 文本链接 | `text-blue-600 hover:opacity-80 transition-opacity` | "更多"、"查看全部"等链接 |

**布局核心：** Flex 优先，固定尺寸 + 自适应填充

```scss
.container {
  display: flex;
  gap: 12px;
  
  .fixed { flex: 0 0 20%; }
  .flexible { flex: 1; min-width: 0; }
}
```

**常用模式：**

| 场景 | 类名 |
|------|------|
| 横向排列 | `flex items-center gap-3` |
| 纵向排列 | `flex flex-col gap-3` |
| 两端对齐 | `flex items-center justify-between` |
| 完全居中 | `flex items-center justify-center` |

## 4. 代码规范

### 标签说明

| 标签 | 含义 |
|------|------|
| **【必须】** | 违反即视为未完成 |
| **【禁止】** | 不要做 |
| **【建议】** | 默认遵循，有充分理由可偏离并说明 |
| **【大文件】** | 仅单文件 >800 行、三栏控制台页、或单 region >200 行时适用 |

### 4.1 命名规范

| 类型 | 命名 | 示例 |
|------|------|------|
| 组件 | PascalCase | `UserProfile.vue` |
| 组合式函数 | camelCase with `use` | `useAuth.ts` |
| 工具函数 | camelCase | `formatDate.ts` |
| 类型 | PascalCase | `UserType.ts` |

### 4.2 代码组织

**组件内部顺序：** Props → Emits → 状态 → 计算属性 → 方法 → 生命周期

```typescript
<script setup lang="ts">
// 1. Props
interface Props { userId: string; }
const props = defineProps<Props>();

// 2. Emits
const emit = defineEmits<{ submit: [data: object] }>();

// 3. 状态
const count = ref<number>(0);

// 4. 计算属性
const displayCount = computed(() => `数量: ${count.value}`);

// 5. 方法
const handleSubmit = () => { emit('submit', {}); };

// 6. 生命周期
onMounted(() => { });
</script>
```

**类型规范：**
- Props、Emits、响应式状态都需要清晰类型
- 派生数据放入 `computed`
- 列表渲染必须提供稳定的 `key`
- **每行语句末尾加分号**

### 4.3 路由规范

- 路径使用 kebab-case：`/divination`, `/user-profile`
- name 使用 camelCase：`name: 'divination'`
- 导航使用：`router.push({ name: 'divination' })`

### 4.4 状态管理（Pinia）

**Store 命名：** `useXxxStore.ts`

```typescript
export const useUserStore = defineStore('user', () => {
  const userInfo = ref<UserInfo | null>(null);
  const isLoggedIn = computed(() => !!userInfo.value);
  const setUserInfo = (info: UserInfo) => { userInfo.value = info; };
  
  return { userInfo, isLoggedIn, setUserInfo };
});
```

### 4.5 文件命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 视图文件 | PascalCase + View.vue | `HomeView.vue` |
| 组件文件 | PascalCase.vue | `TabBar.vue` |
| Store 文件 | camelCase + Store.ts | `useUserStore.ts` |

### 4.6 错误处理

```typescript
const fetchData = async () => {
  loading.value = true;
  try {
    const result = await api.getData();
    data.value = result;
  } catch (error) {
    console.error('获取数据失败:', error);
    showToast('获取数据失败，请重试');
  } finally {
    loading.value = false;
  }
};
```

### 4.7 方法注释规范

**【必须】** 凡属「方法」必须有注释，写用途/边界/副作用，不重复函数名。

**算方法（必注）：** `function` / `async function`；`const fn = () =>`；composable 与工具文件中的函数。

**可不注：** 模板内联一行箭头；不应存在的 `.value` 包装函数；`interface`/常量（靠 region 说明）。

**四要素（有则写，无则写「无」）：**

1. 做什么（业务目的，非复述函数名）
2. 入参 / 返回值要点
3. 边界（空值、根节点、权限等）
4. 副作用（改 ref、请求、弹窗、emit）

```typescript
/** 加载卦象列表；失败清空列表，不改动当前选中项 */
async function loadHexagramList(): Promise<void> { … }

/** 获取指定卦象的解读；入参 id 为卦象编号，返回解读文本或 null */
function getInterpretation(id: string): string | null { … }
```

**【必须】** 注释在函数正上方；改函数同步改注释。

### 4.8 少拆子方法原则

**【必须】** 默认一段业务流程写在一个函数里，从上到下读通；不为「整洁」拆成多个小函数 / composable 片段。

**【必须】** 任意拆分会增加跳读成本；优先**一次读通**，而非抽象分层美观。

仅在以下情况才拆：
- 同一逻辑**多处复用**
- 单函数**明显过长**（如 >80 行），且拆后每段仍自成一体
- 符合大文件拆分条件（见 4.9），且**必须先确认**

composable、工具函数、类内逻辑**同样遵守**；不因「可复用」之名做一次性拆分。

### 4.9 大文件组织

> 以下规则 **不** 用于 <300 行的弹窗、小组件；小文件保持平铺即可。

**何时考虑拆分：**
- 单文件 >800 行
- ≥3 个独立 UI 区域（如左/中/右）
- 单个 `//#region` >200 行

**Region 命名：** `//#region 左侧·类型树` / `//#endregion`；前缀：`左侧·` `中间·` `右侧·` `顶部·` `底部·`。

**Script 顺序：** `类型定义` → `组合式 API` → `常量` → `页面状态` → `按 UI 位置的 region` → `弹框与批量` → `Watch/生命周期`。

**Region 内子分类（固定顺序）：** `State` → `Computed` → `工具函数` → `类型判断` → `增删改查` → `移动排序` → `右键菜单` → `交互处理`。

**函数顺序：** 先声明后使用；纯函数在前，请求/改状态在后；相关函数相邻。

**拆分方案：** 按区域拆 composable（参考 `useHexagramList` / `useInterpretation`）。

**【必须】** composable 之间不互相 import；通过 `options` 注入 `getHexagram`、`onHexagramChange` 等。

**【建议】** 主文件保留：composable 组装、跨区 computed、`h()` 右键菜单、watch/生命周期；样式留在 `.vue` 的 `<style>`。

### 4.10 数据与类型映射

**原则（三层，只映射一次）：**

```
数据层     Record<string, unknown>  ← SQLite 查询结果或本地 JSON
           ↓ 至多一次 map（进页面/树/表前）
视图层     HexagramNode 等          ← 仅含页面用到的字段，可有 label 等展示名
提交层     对象字面量               ← 字段名与数据模型一致
```

| 规则 | 说明 |
|------|------|
| **【必须】** | 响应列表/树：`ref<Record<string, unknown>[]>` 或单次 `mapXxxToView` 进视图类型 |
| **【禁止】** | `XxxApiNode` + `mapApi` + `mapNode` + `mapRow` 多层映射 |
| **【禁止】** | 在 map 里改字段名（`isListable` → `showInTable`）；改名只允许视图字段（如 `text`→`label`） |
| **【必须】** | 原始值保留；展示名用**新 key**（`dataType` + `dataTypeName`），不覆盖原字段 |
| **【建议】** | 视图 `type` 只声明页面用到的字段，不复制完整模型 |

**枚举处理：**

```typescript
export enum EnumXxx { A = 0, B = 1 }
export const XxxMap: Record<number, string> = { 0: '标签 A', 1: '标签 B' }
export const Xxx_OPTIONS: string[] = ['标签 A', '标签 B']
```

**【必须】** `XxxMap` 的 key 为数字字面量；展示用 `Xxx_OPTIONS` 等字符串字面量。

**【必须】** 接口 int 枚举 → 展示 label 走工具函数，禁止 `=== 1 ? '字符串'`。

### 4.11 Loading 管理

**【建议】** 同一可见区域一个 loading ref（如 `hexagramListLoading`）；弹窗 `:loading` 可单独 ref。

### 4.12 异步处理策略

| 场景 | 做法 |
|------|------|
| 单请求、分支简单 | `.then/.catch` |
| 多请求顺序、中间变量多 | `async/await` |
| 需 `try/finally` 统一收尾 | `async/await` 或 `.finally` |

### 4.13 提示与反馈规范（Toast）

**【必须】** 所有用户可感知的提示统一使用 Vant 的 Toast 函数式 API，参照 [Vant Toast 规范](https://vant-ui.github.io/vant/#/zh-CN/toast)。

**API 选择：**

| 场景 | API | 示例 |
|------|-----|------|
| 普通文字提示（校验失败、轻反馈） | `showToast` | `showToast('请为六爻各选一爻值')` |
| 操作成功 | `showSuccessToast` | `showSuccessToast('已清空记录')` |
| 操作失败 / 异常 | `showFailToast` | `showFailToast('加载失败，请重试')` |
| 加载中 | `showLoadingToast` | `showLoadingToast({ message: '加载中...', forbidClick: true })` |
| 主动关闭 | `closeToast` | 配合 `duration: 0` 的加载提示使用 |

**引入方式：** 显式 `import { showToast, showSuccessToast, showFailToast, showLoadingToast, closeToast } from 'vant';`（项目已全量引入 `vant/lib/index.css`，显式导入安全，类型友好）。

**强制规则：**

- **【禁止】** 使用 `alert` / `confirm` / `window.confirm` / `window.alert` 等浏览器原生弹窗。
- **【必须】** 用户可感知的操作失败（加载、删除、保存、清空等）在 `catch` 中除 `console.error` 外，必须 `showFailToast` 给用户反馈；纯数据层（如 `db.ts`）只 `console.error`，由调用方负责提示。
- **【建议】** 成功的写操作（删除、清空、保存）追加 `showSuccessToast` 轻反馈；只读加载成功不提示。
- **【建议】** 加载场景用 `showLoadingToast({ forbidClick: true })`，在 `finally` 或完成后 `closeToast()`；默认 `duration: 2000` 已足够，不要传 `duration: 0` 除非手动控制关闭。
- **【建议】** 文案简洁，一句话说清状态，不带标点结尾；避免「失败：」这种冗余前缀（图标已表达语义）。

**示例：**

```typescript
import { showToast, showSuccessToast, showFailToast } from 'vant';

const deleteRecord = async (id: number) => {
```

## 7. 自检清单

**基础规范：**
- [ ] 使用 Vant UI 组件
- [ ] 样式优先使用 UnoCSS
- [ ] 自定义样式使用 Sass
- [ ] 每行语句末尾加分号
- [ ] 颜色使用主色调（blue-600）
- [ ] 布局使用 Flex 优先
- [ ] 提示统一用 Vant Toast（showToast/Success/Fail/Loading），禁止 alert/confirm
- [ ] 可感知的操作失败 catch 内有 showFailToast 反馈

**组件规范：**
- [ ] Props/Emits/状态有清晰类型
- [ ] 按顺序组织代码
- [ ] 派生数据放入 computed
- [ ] 列表渲染提供 key

**路由与状态：**
- [ ] 路由路径使用 kebab-case
- [ ] 路由 name 使用 camelCase
- [ ] Store 使用 useXxxStore 命名
- [ ] 异步操作有 try-catch

**注释与代码组织：**
- [ ] 方法有注释（做什么/入参返回/边界/副作用）
- [ ] 业务流程优先写在一个函数里，不随意拆子方法
- [ ] 大文件（>800行）按 region 组织，拆分前先确认

**数据与类型：**
- [ ] 数据只映射一次，不做多层 map
- [ ] 枚举展示走工具函数，禁止魔法数字
- [ ] 视图类型只声明页面用到的字段

**文件与资源：**
- [ ] 视图文件以 View.vue 结尾
- [ ] 组件文件使用 PascalCase
- [ ] 更新了 开发日志.md
