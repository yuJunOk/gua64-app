# Gua64 数据库设计文档

## 一、数据存储概述

### 基本信息
- **数据库名称**: `gua64`
- **数据库类型**: SQLite（移动端）/ 内存数据库（Web开发环境）
- **版本**: v2.0
- **字符集**: UTF-8

### 设计原则
1. **动静分离**: 易经知识数据（静态）以 JSON 文件形式内置，用户数据（动态）存入 SQLite
2. **数据本地化**: 所有数据存储在本地，无需联网
3. **离线可用**: 完全支持离线运行
4. **扩展性**: 表结构设计考虑未来功能扩展

### 数据存储架构

```
┌─────────────────────────────────────────────────────┐
│                    数据存储层                          │
│                                                     │
│  ┌───────────────────────┐  ┌─────────────────────┐ │
│  │   静态知识数据（JSON文件）│  │  用户数据（SQLite）  │ │
│  │                       │  │                     │ │
│  │  • 八卦表（8条）       │  │  • divination       │ │
│  │  • 六十四卦（64条）    │  │  • collection       │ │
│  │  • 卦辞文献（64条）    │  │  • category         │ │
│  │  • 爻辞信息（384条）   │  │  • tag              │ │
│  │                       │  │  • divination_tag   │ │
│  │  特点：永不变化        │  │  • app_settings     │ │
│  │  方式：JSON文件加载    │  │                     │ │
│  └───────────────────────┘  │  特点：用户产生      │ │
│                             │  方式：SQLite持久化  │ │
│                             └─────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

## 二、静态知识数据（JSON 文件）

以下数据为易经固定知识，永不变化，以 JSON 文件形式维护，应用启动时加载到内存。

### 1. 八卦数据（trigrams）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | number | 八卦ID（1-8） |
| `name` | string | 卦名（乾、坤、震、巽、坎、离、艮、兑） |
| `symbol` | string | 符号（如：111、000） |
| `nature` | string | 性质（天、地、雷、风、水、火、山、泽） |

**八卦对应表**:

| ID | 八卦 | 符号 | 性质 |
|----|------|------|------|
| 1 | 乾 | 111 | 天 |
| 2 | 坤 | 000 | 地 |
| 3 | 震 | 001 | 雷 |
| 4 | 巽 | 110 | 风 |
| 5 | 坎 | 010 | 水 |
| 6 | 离 | 101 | 火 |
| 7 | 艮 | 100 | 山 |
| 8 | 兑 | 011 | 泽 |

### 2. 六十四卦数据（hexagrams）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | number | 卦ID，范围1-64 |
| `name` | string | 卦名（如：乾、坤、屯、蒙） |
| `sequence` | number | 卦序（1-64） |
| `upperTrigramId` | number | 上卦ID（1-8，对应八卦） |
| `lowerTrigramId` | number | 下卦ID（1-8，对应八卦） |
| `symbol` | string | 卦象符号（六爻组合，如：111111） |
| `nature` | string | 卦性（如：乾为天、坤为地） |
| `category` | string | 八宫分类（如：乾宫、坤宫） |

**卦象符号说明**:
- `1` 代表阳爻（━）
- `0` 代表阴爻（--）
- 六爻从下到上排列，如乾卦为 `111111`，坤卦为 `000000`

### 3. 卦辞文献数据（hexagramLiterature）

每条记录关联对应卦（通过 `hexagramId`），包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `hexagramId` | number | 关联卦ID（1-64） |
| `fortune` | string | 吉凶平（如：吉、凶、平、吉带凶） |
| `hexagramText` | string | 卦辞原文 |
| `hexagramTextTranslation` | string | 卦辞译文 |
| `tuanText` | string | 彖辞（彖曰原文） |
| `tuanTextTranslation` | string | 彖辞译文 |
| `xiangText` | string | 象辞（大象曰原文） |
| `xiangTextTranslation` | string | 象辞译文 |
| `heloNumber` | string | 河洛理数 |
| `summary` | string | 卦义总结 |

### 4. 爻辞数据（yaoData）

每条记录关联对应卦（通过 `hexagramId`）和爻位，包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `hexagramId` | number | 关联卦ID（1-64） |
| `position` | number | 爻位（1-6，从下往上数） |
| `yaoType` | string | 爻性（如：初九、九二、六三、上六） |
| `fortune` | string | 吉凶平（如：吉、凶、悔、吝） |
| `yaoText` | string | 爻辞原文 |
| `yaoTextTranslation` | string | 爻辞译文 |
| `xiangText` | string | 象曰原文（小象） |
| `xiangTextTranslation` | string | 象曰译文 |
| `heloNumber` | string | 河洛理数 |

### 静态数据文件规划

| 文件路径 | 内容 | 数据量 |
|----------|------|--------|
| `src/data/trigrams.json` | 八卦数据 | 8 条 |
| `src/data/hexagrams.json` | 六十四卦基础数据 | 64 条 |
| `src/data/hexagram-literature.json` | 卦辞文献数据 | 64 条 |
| `src/data/yao-data.json` | 爻辞数据 | 384 条 |

### 静态数据使用示例

```ts
import trigrams from '@/data/trigrams.json'
import hexagrams from '@/data/hexagrams.json'
import hexagramLiterature from '@/data/hexagram-literature.json'
import yaoData from '@/data/yao-data.json'

// 根据卦序获取卦信息
const hexagram = hexagrams.find(h => h.sequence === 1)
// → { id: 1, name: '乾', symbol: '111111', nature: '乾为天', ... }

// 获取对应卦辞
const literature = hexagramLiterature.find(l => l.hexagramId === hexagram.id)
// → { fortune: '吉', hexagramText: '元亨利贞', ... }

// 获取对应爻辞
const yaos = yaoData.filter(y => y.hexagramId === hexagram.id)
// → [{ position: 1, yaoType: '初九', yaoText: '潜龙勿用', ... }, ...]
```

## 三、数据库表结构（用户数据）

### 1. divination（卦局记录表）⭐ 核心表

记录用户每次起卦的完整结果，是整个应用的核心数据表。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 卦局ID |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO格式） |
| `divination_time` | TEXT | | 起卦时间（用户指定的起卦时间，ISO格式） |
| `question` | TEXT | | 所占之事（用户输入的问题） |
| `title` | TEXT | | 自定义标题（默认使用卦名） |
| `original_hexagram_seq` | INTEGER | NOT NULL | 本卦卦序（1-64，对应静态数据） |
| `changed_hexagram_seq` | INTEGER | | 变卦卦序（1-64，无变爻时为NULL） |
| `yao_values` | TEXT | NOT NULL | 六爻数值（JSON数组，如 [7,8,9,6,7,8]） |
| `moving_yao_positions` | TEXT | | 动爻位置（JSON数组，如 [3,4]，从下往上数） |
| `result_type` | TEXT | NOT NULL | 起卦方式（auto：自动起卦，manual：手动录入） |
| `is_collected` | INTEGER | DEFAULT 0 | 是否已收藏（0：否，1：是） |
| `note` | TEXT | | 个人笔记 |

> **设计说明**：`original_hexagram_seq` 和 `changed_hexagram_seq` 存储卦序（1-64），通过卦序在静态数据中查找对应卦信息，无需外键约束。

**动爻判定规则**（根据三枚硬币摇卦法）:
- `6`: 老阴，动爻，变阳
- `7`: 少阳，静爻
- `8`: 少阴，静爻
- `9`: 老阳，动爻，变阴

---

### 2. collection（收藏表）

记录用户收藏的卦局，支持分类管理。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 收藏ID |
| `divination_id` | INTEGER | NOT NULL, FOREIGN KEY, UNIQUE | 关联卦局ID（一个卦局只能收藏一次） |
| `category_id` | INTEGER | FOREIGN KEY | 分类ID（NULL表示未分类） |
| `collected_at` | TEXT | NOT NULL | 收藏时间 |

**外键约束**:
```sql
FOREIGN KEY (divination_id) REFERENCES divination(id) ON DELETE CASCADE
FOREIGN KEY (category_id) REFERENCES category(id) ON DELETE SET NULL
```

---

### 3. category（分类表）

收藏分类管理，用户可自定义分类名称和颜色。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 分类ID |
| `name` | TEXT | NOT NULL | 分类名称（如：事业、财运、感情） |
| `color` | TEXT | DEFAULT '#3B82F6' | 分类颜色（十六进制颜色值） |
| `icon` | TEXT | | 分类图标（emoji或图标名称） |
| `sort_order` | INTEGER | DEFAULT 0 | 排序顺序 |

---

### 4. tag（标签表）

卦局标签管理，用于搜索和筛选。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 标签ID |
| `name` | TEXT | NOT NULL UNIQUE | 标签名称（如：工作、考试、健康） |
| `color` | TEXT | DEFAULT '#6B7280' | 标签颜色 |

---

### 5. divination_tag（卦局标签关联表）

卦局与标签的多对多关系表。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 关联ID |
| `divination_id` | INTEGER | NOT NULL, FOREIGN KEY | 关联卦局ID |
| `tag_id` | INTEGER | NOT NULL, FOREIGN KEY | 关联标签ID |

**外键约束**:
```sql
FOREIGN KEY (divination_id) REFERENCES divination(id) ON DELETE CASCADE
FOREIGN KEY (tag_id) REFERENCES tag(id) ON DELETE CASCADE
```

**唯一约束**:
```sql
UNIQUE (divination_id, tag_id)
```

---

### 6. app_settings（应用设置表）

存储应用的个性化设置。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 设置ID |
| `key` | TEXT | NOT NULL UNIQUE | 设置键（如：theme、font_size） |
| `value` | TEXT | NOT NULL | 设置值 |
| `description` | TEXT | | 设置描述 |

**预设设置项**:

| key | value | description |
|-----|-------|-------------|
| `theme` | `light` | 主题（light/dark/system） |
| `font_size` | `normal` | 字体大小（small/normal/large） |
| `coin_style` | `yuan` | 硬币样式（yuan/tong/modern） |
| `auto_save` | `1` | 自动保存历史（0/1） |
| `show_animation` | `1` | 显示动画效果（0/1） |

## 五、核心业务流程

### 1. 起卦流程

```
用户输入占事 → 选择起卦方式（自动/手动）
    │
    ├─ 自动起卦：系统随机生成6个爻值(6-9)
    │       │
    │       ▼
    │  计算本卦卦序、变卦卦序、动爻位置
    │
    └─ 手动录入：用户依次输入6个爻值(6-9)
            │
            ▼
     保存到 divination 表（存储卦序，非外键）
            │
            ▼
     从静态数据加载卦名、卦象（hexagrams[seq-1]）
            │
            ▼
     从静态数据加载卦辞文献（hexagramLiterature）
            │
            ▼
     从静态数据加载各爻详细信息（yaoData）
            │
            ▼
     展示卦局结果
```

### 2. 收藏流程

```
用户点击收藏 → 判断是否已收藏
                    │
                    ├─ 已收藏：取消收藏（删除collection记录 + divination.is_collected置0）
                    │
                    └─ 未收藏：添加收藏（插入collection记录 + divination.is_collected置1）
```

> **注意**：`divination.is_collected` 作为缓存字段，与 `collection` 表保持同步更新，用于列表页快速判断收藏状态，避免每次 JOIN 查询。

### 3. 搜索流程

```
用户输入关键词 → 搜索 divination 表
                    │
                    ├─ 按卦名搜索：通过 original_hexagram_seq 关联静态数据中的卦名
                    ├─ 按标题搜索：divination.title
                    ├─ 按问题搜索：divination.question
                    ├─ 按笔记搜索：divination.note
                    └─ 按标签搜索：关联 tag → divination_tag
```

## 七、数据库初始化脚本

```sql
-- 创建卦局记录表
CREATE TABLE IF NOT EXISTS divination (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL,
    divination_time TEXT,
    question TEXT,
    title TEXT,
    original_hexagram_seq INTEGER NOT NULL,
    changed_hexagram_seq INTEGER,
    yao_values TEXT NOT NULL,
    moving_yao_positions TEXT,
    result_type TEXT NOT NULL,
    is_collected INTEGER DEFAULT 0,
    note TEXT
);

-- 创建收藏表
CREATE TABLE IF NOT EXISTS collection (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    divination_id INTEGER NOT NULL UNIQUE,
    category_id INTEGER,
    collected_at TEXT NOT NULL,
    FOREIGN KEY (divination_id) REFERENCES divination(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES category(id) ON DELETE SET NULL
);

-- 创建分类表
CREATE TABLE IF NOT EXISTS category (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    color TEXT DEFAULT '#3B82F6',
    icon TEXT,
    sort_order INTEGER DEFAULT 0
);

-- 创建标签表
CREATE TABLE IF NOT EXISTS tag (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    color TEXT DEFAULT '#6B7280'
);

-- 创建卦局标签关联表
CREATE TABLE IF NOT EXISTS divination_tag (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    divination_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    FOREIGN KEY (divination_id) REFERENCES divination(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tag(id) ON DELETE CASCADE,
    UNIQUE (divination_id, tag_id)
);

-- 创建应用设置表
CREATE TABLE IF NOT EXISTS app_settings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    key TEXT NOT NULL UNIQUE,
    value TEXT NOT NULL,
    description TEXT
);

-- 创建索引
CREATE INDEX IF NOT EXISTS idx_divination_created ON divination(created_at);
CREATE INDEX IF NOT EXISTS idx_divination_hexagram ON divination(original_hexagram_seq);
CREATE INDEX IF NOT EXISTS idx_divination_collected ON divination(is_collected);
CREATE INDEX IF NOT EXISTS idx_collection_category ON collection(category_id);

-- 插入预设应用设置
INSERT OR IGNORE INTO app_settings (key, value, description) VALUES
('theme', 'light', '主题设置（light/dark/system）'),
('font_size', 'normal', '字体大小（small/normal/large）'),
('coin_style', 'yuan', '硬币样式（yuan/tong/modern）'),
('auto_save', '1', '自动保存历史记录（0/1）'),
('show_animation', '1', '显示动画效果（0/1）');
```

## 九、版本升级策略

### 数据库版本管理

当需要修改表结构时，采用版本号管理：

1. **v2.0**: 初始版本，静态知识数据外置为 JSON 文件，数据库仅存储用户数据（6张表）
2. **v2.1+**: 新增表或字段，通过 ALTER TABLE 语句升级

### 升级脚本示例

```sql
-- v2.1 升级脚本示例（新增字段）
ALTER TABLE divination ADD COLUMN ai_interpretation TEXT;

-- v2.2 升级脚本示例（新增表）
CREATE TABLE IF NOT EXISTS divination_stats (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    hexagram_seq INTEGER NOT NULL,
    occur_count INTEGER DEFAULT 0,
    last_occurred_at TEXT
);
```

### 静态数据更新

静态知识数据如需修正或补充（如发现卦辞有误），直接修改对应 JSON 文件，随应用版本发布即可。无需数据库迁移。

## 十一、安全考虑

### 数据加密

- SQLite 数据库支持加密（使用 `@capacitor-community/sqlite` 的加密选项）
- 敏感数据（如个人笔记）在存储前进行加密处理

### 数据隔离

- 每个用户的数据完全隔离
- 数据仅存储在本地，不上传云端

## 十二、性能优化

### 查询优化

1. **静态数据内存缓存**: JSON 文件加载后常驻内存，查询零延迟
2. **分页查询**: 历史记录查询支持分页，避免一次性加载大量数据
3. **索引优化**: 关键查询字段建立索引

### 存储优化

1. **动静分离减少数据库体积**: 静态知识数据不占数据库空间，SQLite 仅存储用户数据
